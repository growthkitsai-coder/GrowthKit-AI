# Pages — every HTML file in the repo

> Part of the GrowthKit AI docs set. Read [`CLAUDE.md`](../CLAUDE.md) first — it holds the non-negotiable mandates and conventions. This file is the deep reference for what each page is and contains. **If you add, remove, or materially change a page, update this file** (and follow the new-page checklist in [`docs/infrastructure.md`](infrastructure.md)).

All pages live at the repo root. Every public page is self-contained: inline `<style>` in `<head>`, shared `theme.css`/`theme.js`, duplicated topbar/footer (no templating). Dark-mode treatments referenced below are detailed in [`docs/design-system.md`](design-system.md).

## Auth / app pages (noindex, out of sitemap — see [`docs/auth.md`](auth.md))

- **`login.html`** (`/login`) — email + password + "Continue with Google", remember-me, forgot-password link. On success → `/four`.
- **`signup.html`** (`/signup`) — email + password (8+) + Google; with email confirmation on, shows a "check your email" state. On success → `/four`.
- **`reset.html`** (`/reset`) — password reset: request-a-link form, and (when arriving from the emailed link) a set-new-password form.
- **`four.html`** (`/four`) — **the gated product dashboard and GrowthKit Live workspace**. Free accounts can complete the saved adaptive wizard and see the locked preview; Pro, Agentic, and current beta accounts can generate one full report per UTC day on any company. The ten-stage renderer adds TAM/SAM/SOM, ranked segments, market trend and live indexed-demand charts where available, three GTM plays, window-of-opportunity scoring, funding radar/lists, and weekly metrics from every configured Stripe/GA4/LinkedIn connection to newly generated reports; legacy completed reports keep their original layout. The desktop GrowthKit Live surface is widened to a 1,380px maximum working canvas (48px viewport gutters), while mobile retains 12px gutters. Directly beneath it, `[data-daily-countdown]` reads “Daily report coming in HH:MM:SS” after today's completion and counts to the next 00:00 UTC unlock, then changes to “Daily report ready”; the server remains authoritative. A `[data-beta]` card handles apply/pending/granted/spent states and stays hidden for paid/private-allowlist accounts. `[data-history]` lists reports newest-first and links to `/four?report_id=…`. Above the engine, keep `.four-welcome`, `[data-gk-billing]`, `#four-greeting-h`, and `[data-gk-advisor]` unique: duplicate wrappers cause browser re-parenting and break the layout. Below it are connected-data controls, the specimen iframe, Pro card, and legacy reads. `product.js` owns entitlement/countdown/history/integrations, `advisor.js` owns onboarding and report rendering, and `findings.js` owns working-document actions. See [`daily-intelligence.md`](daily-intelligence.md), [`integrations.md`](integrations.md), and [`advisor.md`](advisor.md).
- All four: `noindex`, no footer, minimal top bar; Supabase Auth via CDN; shared `auth.css` + `auth.js` + `auth-config.js`. **Sign-in is inactive until Supabase keys are pasted into `auth-config.js`** (pages show a "not configured" notice until then).
- **`/four` styling invariant:** the print-only finding-task rules in `auth.css` must close their `@media print` block before the welcome, guide, specimen, and Pro-card rules. An unclosed block makes those dashboard cards render as plain text on screen; the site checker now rejects unbalanced CSS.
