## Known sharp edges / gotchas

- **CLAUDE.md is committed to git.** Do not put secrets, credentials, or PII into it. Same for this memory.md file — treat it as public.
- **🔴 "The engine is broken" is usually an empty Anthropic balance, not a broken key (confirmed 2026-07-24).** A key with no credit still *authenticates* — it returns **HTTP 400 `invalid_request_error`, "Your credit balance is too low to access the Anthropic API"**, not a 401. Nothing in the code distinguishes this from any other failed section, so it surfaces to users as a generic retryable error and looks exactly like a timeout or outage. **Check console.anthropic.com → Plans & Billing before touching keys, env vars, or Vercel projects.** The curl one-liner that tells the three cases apart is in `docs/advisor.md`.
- **The Vercel CLI in this working tree is linked to the WRONG project (confirmed 2026-07-24).** `.vercel/project.json` → `avi-aggarwal14s-projects/growthkit-ai`, which has **no deployments and no domains**, and whose only env var is `ANTHROPIC_API_KEY`. This is the "empty duplicate" from the two-accounts trap. The project actually serving growthkitai.com is on a **different Vercel account** that this CLI session is not logged into — so `vercel env add` / `vercel env ls` run from this repo write to and read from the wrong place, silently. Production env vars must be set in the correct project's dashboard until the link is fixed.
- **`security.html` makes factual claims** (MFA on founder accounts, named vendor list, no payment data, honest "no SOC 2" disclosure). If infrastructure or vendors change, update that page — a wrong security page is worse than none.
- **No templating.** Footer/topbar/`<head>` duplication is intentional but means changes must be replicated by hand across every HTML file. A grep + multi-file edit is the right pattern.
- **`logo.html` is internal.** Don't add it to nav, sitemap, or any public link.
- **Dark-mode body background uses `!important`.** This is deliberate (cascade conflict with per-page inline styles). Don't "clean it up".
- **Pre-paint theme script.** Every `<head>` starts with an inline script that sets `data-theme` before first paint. Removing it causes a flash of incorrect theme.
- **Apps Script deployment.** "New deployment" = new URL = broken waitlist. Always "Manage deployments → New version".
- **GSAP/ScrollTrigger/Lenis are only loaded on `index.html`.** Don't assume they're available on other pages.
- **Subpage topbar nav is standardized** (2026-06-10): Product (`/#engine`) / How it works (`/#process`) / Methodology / Contact. Four older pages carried a dead "Customers → `/#proof`" link for weeks (no such id on index.html) — exactly the silent drift the checker now catches.
- **LinkedIn returns HTTP 999 to bots** — that's why the lychee config accepts 999; don't "fix" it by removing the accept list or LinkedIn links will fail CI forever.
- **Supabase auth redirect trap (seen 2026-07-05):** after a successful Google login, Avi landed on `growthkitai.base44.app/#access_token=…` showing Base44's `{"error_type":"HTTPException","message":"App not found"}`. Auth *worked* (token issued) — the bug is Supabase's **Site URL / Redirect URLs** pointing at the Base44 host instead of `growthkitai.com`, so the requested `redirectTo` (`origin+/four`) isn't allowlisted and Supabase falls back to Site URL (Base44). Fix is dashboard-only (Authentication → URL Configuration): Site URL `https://growthkitai.com`; Redirect URLs `https://growthkitai.com/**` + `http://localhost:3000/**`; remove any base44 entry; then log in from `https://growthkitai.com/login`. **Not a code bug** — `auth.js` uses `origin+'/four'` correctly. If `growthkitai.com/login` itself shows Base44 (not our cream/forest page), the domain's DNS is pointed at Base44, not Vercel — a separate, bigger routing fix to do first.
